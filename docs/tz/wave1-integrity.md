# ТЗ агенту 4: CLI, протокол целостности, тесты без модели

## Роль

Ты продумываешь **только** пользовательский контракт Go-утилиты и что значит «целостность» для lossy-кодеков. Не проектируй NF4 LUT и не байты CHR0 — сошлись на имена полей из соседних спек (`docs/spec/chr0.md` может ещё писаться: опирайся на `docs/compressor.md` §6 и ТЗ 1–3).

## Зафиксировано (не спорь)

- Язык: Go 1.22, модуль `chr`, без CGO, стандартная библиотека + ничего тяжёлого. Допустим только то, что нужно для тестов (`testing`).
- CLI бинарь: `chr` из `cmd/chr`.
- Команды минимум:
  - `chr compress --in <safetensors|dir> --out <file.chr> --codec nf4|vq`
  - `chr decode --in <file.chr> --out <out.safetensors>` (один файл, не шарды)
  - `chr verify --orig <safetensors|dir> --chr <file.chr>`
- Модель **не скачивать** ни в спеке, ни потом в реализации этой волны. Фикстуры — крошечные safetensors, которые тест сам пишет.
- Целостность **не** «бит-в-байт равенство с BF16». Кодек lossy. Различай три уровня:
  1. контейнер: повторное чтение `.chr` даёт те же блобы;
  2. кодек: decode(pack) совпадает с эталоном из `docs/spec/nf4.md` / `vq.md`;
  3. вес: метрики orig vs reconstruct.
- Нормы и bias: roundtrip **бит-точный** BF16.
- Код выхода: 0 ок, 1 ошибка ввода, 2 провал порога verify.
- Не грузить все тензоры сразу в verify: как compress, по одному.

## Напиши файл `docs/spec/integrity-cli.md`

До мелочей. Обязательные разделы:

1. Флаги, дефолты (`--group-size`, `--seed`, `--iters`, `--chunk`, `--fail-rmse`, `--fail-maxabs`). Дефолтные пороги: для nf4 и vq **разные**. Предложи числа для синтетики и **отдельные** более свободные для будущей живой 8B (в спеке пометь «для живой модели, не для unit-тестов»).
2. Печать verify: на тензор — name, shape, codec, rmse, maxabs, mae, n. В конце — худший тензор и summary. Формат: человеческий текст + опционально `--json`.
3. Что сравнивать, если в `.chr` нет какого-то тензора из orig (пропуск vs ошибка). Выбери: все веса из orig, которые классифицируются как compressable, должны быть в chr; extra в chr — ошибка.
4. `decode` пишет safetensors в **F32** (проще для проверки) или BF16? Выбери F32 для decode-проверки, зафиксируй.
5. Список unit/golden тестов (имена тест-функций Go) без модели: контейнер, nf4 golden, vq toy, verify fail code, pad, multi-tensor fake model из 3 тензоров. Для каждого: что arrange/assert.
6. Как руками потом прогнать живую модель (раздел «после скачивания») — команды, без самих весов в репо.
7. Границы памяти: не читать шарды параллельно; лимит «один тензор». Если тензор больше RAM — полосы строк (спека должна сказать, с какого размера, и что книга VQ тогда двухпроходная: init по первым полосам / subsample, assign по всем). Для v1 unit-тестов полосы можно не включать, но для живого 1.6 ГБ lm_head — да. Распиши.

## Не делай

- Не пиши код (кроме крошечных примеров командных строк).
- Не качай модели.
- Не `git checkout`. Не меняй файлы кроме `docs/spec/integrity-cli.md`.

## Критерий готовности

Вторая волна может нарезать пакеты `cmd/chr`, `internal/verify` и таблицу тестов один-в-один по твоему списку.
