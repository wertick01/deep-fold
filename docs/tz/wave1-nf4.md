# ТЗ агенту 2: кодек NF4 (CPU, group 64)

## Роль

Ты продумываешь **только** кодек A: group-wise NF4 как QLoRA / bitsandbytes, на CPU, для roundtrip целостности. Не проектируй контейнер и не VQ.

## Зафиксировано (не спорь)

- Группа по оси **K / n_in** (последняя ось row-major матрицы `W[n_out, n_in]`). `group_size = 64`.
- Шкала группы: `s = max(|g|)`; если 0 → `s = 1`. Шкала хранится **FP16** (IEEE 754 binary16), не BF16.
- Уровни — **фиксированные 16 квантилей NF4** из bitsandbytes / QLoRA (Dettmers et al. 2023). Книгу не учим. Double-quant шкал нет.
- Упаковка: `[n_out, n_in_padded/2]` uint8. Байт `data[r, c]`: младшие 4 бита = вес `W[r, 2c]`, старшие = `W[r, 2c+1]`. Значение ниббла = индекс 0..15 в таблице, **не** смещённый INT4.
- Если `n_in % 64 != 0`: паддинг нулями **только при кодировании**; в метаданных логический `shape` без паддинга; при decode обрезать до логического `n_in`.
- Вход может быть F32, F16 или BF16. Счёт квантования — в float32. Выход decode для verify — float32, затем сравнение с оригиналом в float32.
- Таблица NF4 должна **байт-в-байт** совпасть с bitsandbytes (`NF4_LEVELS` / `get_nf4_quant_table`). Найди точные 16 float32 и впиши их в спеку как литералы. Не вычисляй квантили заново.

## Напиши файл `docs/spec/nf4.md`

До мелочей. Обязательные разделы:

1. Таблица из 16 уровней (index 0 = −1.0 … index 15 = +1.0) — точные литералы.
2. Encode одного вектора длины 64: формулы, порядок (max abs → деление → nearest по L2 в float32 → индекс). Что при ties (два уровня одинаково близко)? Выбери правило (например меньший индекс, или как bnb) и зафиксируй.
3. Decode: `w = lut[nib] * s`, в каком порядке множить, нужно ли промежуточно в FP16. Для целостности: decode в float32, шкала сначала FP16→float32.
4. Псевдокод матрицы: цикл по строкам и группам. Сложность, пик памяти (можно стримить по строкам).
5. Упаковка/распаковка нибблов: битовые маски, little-endian машины (x86_64, Windows/WSL). Тестовый вектор из 2 весов → 1 байт, с численным примером.
6. Паддинг, пустые строки, NaN/Inf: что делать. Выбери: NaN/Inf в группе — ошибка encode (не молча).
7. Инварианты для тестов **без модели**:
   - нулевая матрица → все нибблы = индекс нуля в LUT, scale=1;
   - константа `c` на группе → один уровень, scale=`|c|` (если c≠0);
   - decode(encode(W)) идемпотентен относительно второго decode (повторный encode того же decode даёт те же нибблы и шкалы, с оговоркой FP16 scale);
   - пороги: для случайного N(0,1) RMSE после NF4 типично ≪ 0.1; для тестов зафиксируй **жёсткие** пороги на фикстурах, которые сам посчитаешь вручную на матрице 2×64.
8. Золотой пример: выпиши 64 числа (простые: `i/63` или явный массив), ожидаемый `s`, 32 байта packed (hex), 1×FP16 scale bits.
9. Стык с CHR0: shapes блобов, `group_size: 64`. Не описывай JSON целиком.
